## 2. 术语表（先读这一节，后文所有行话在此定义）

| 术语 | 含义 |
|---|---|
| 损失（loss） | 训练时衡量模型预测与标准答案差距的数值。SFT 阶段用的是交叉熵损失，模型靠最小化它来学习 |
| 标签 -100 | PyTorch 约定：标签为 -100 的 token 不参与损失计算。本项目 SFT 只在**助手回复**的 token 上计算损失，系统提示和用户提问全部标 -100 |
| 残段（不完整回复） | 一条助手回复被训练窗口截断，只保留开头、结尾丢失。旧代码把这种"半截话"也划入损失区间，等于教模型生成没有结尾的回答 |
| 零损失样本 | 截断后一条样本不含任何完整助手回复 → 所有 token 标签都是 -100 → 损失恒为 0 → 不产生任何梯度。GPU 前向计算照做，训练效果为零（旧报告称"白训"） |
| 完整回复保留率 | 多轮对话中的助手回复，截断后仍完整保留的比例。基线 45.6%：平均每条对话 4.54 个回复只剩 2.19 个完整（旧报告称"区间存活率"） |
| 拦腰截断 | 旧截断方式：渲染后的对话超过窗口长度时，直接保留前 N 个 token、丢弃其余——切口落在哪个位置不管，常把某条回复切成两半 |
| 轮次边界截断 | 新截断策略：超长对话从最旧的一轮开始整轮丢弃，保证留下的每轮问答都完整 |
| 尾部切片验证集 | 旧切分方式：从数据文件末尾切一小段当验证集。因为数据文件按类别有序排列（前段全是单轮、末段多轮占 39.4%），导致验证集分布严重偏离训练集 |
| 哈希分桶切分 | 新切分方式：按每行内容的哈希值决定归属（哈希取模命中则进验证集），与文件顺序无关，分布无偏 |
| 底座 | 预训练阶段产出的基座权重（`out/pretrain_768.pth`），SFT / DPO 都在它之上继续训练 |
| 续训（继续预训练） | 加载现有底座权重、换更长的训练窗口、用更低的学习率继续预训练——区别于从随机初始化从头训 |
| 回放（replay）数据 | 续训时混入一部分原始短文档，防止模型适应长文档后遗忘短文本能力 |
| 基线测量（定标） | 动手改之前先用工具实测一遍现状数字，作为日后对比的基准 |
| YaRN 外推 | 一种免训练的位置编码插值技术：通过数学变换让只在短窗口训练过的模型能处理更长输入。项目已有开关（`inference_rope_scaling`），但当前配置有错误（见 §6.1） |
| 在题 | 评测用语：模型的回答与问题相关（不跑题） |
| 套件 A/B/C/D | `eval_multiturn.py` 的四组测试：A=跨轮记忆召回，B=上下文长度压力（256~2048 token），C=12 轮长会话稳定性，D=超长输入边界 |

## 3. 问题是什么（背景与现状）

### 3.1 训练管线如何损坏了数据（机制 + 实测数字）

**问题一：预训练阶段，45% 的 token 从未进入训练。**
预训练窗口只有 380 token，而数据集中 30.7% 的文档超过这个长度。超长文档被截断后丢弃的部分，实测占全部 token 的 **45.2%**（保留率 54.8%）。长文档恰恰是模型学习"长距离上下文"的原料。

**问题二：SFT 阶段的截断方式产生三种损坏。**
SFT 窗口 768 token，50.6% 的会话超长（多轮对话子集 82.3% 超长）。旧的截断方式是"保留前 768 个 token"，由此产生：

| 损坏 | 机制 | 实测数字 |
|---|---|---|
| 不完整回复被当作学习目标 | 回复结尾被切掉，但开头仍在窗口内，损失区间判定把它当作学习目标 | 每条受损样本平均 0.82 个残段——模型反复学"没有结尾的半截话"，与生成实测中"回答戛然而止、复读"直接对应 |
| 零损失样本 | 截断把所有完整回复都切掉了，全部标签 -100，损失恒 0，零梯度 | 占多轮样本 **5.7%**，纯耗 GPU |
| 完整回复大量丢失 | 多轮对话后半段被整段丢弃 | 保留率仅 **45.6%**；结合受损比例，多轮监督信号只剩名义值的约 37% |

**问题三：数据本身的重复与失衡。**
助手回复内容完全相同的占 **8.6%**（同一答案反复出现会强化背诵式复读）；多轮样本只占 **19.4%**（单轮:多轮 = 4:1，学"接着聊"的原料本身就少）。

**问题四：验证集切偏，训练分数不可信。**
数据文件按构造有序（前段 100% 单轮、末段 39.4% 多轮），旧的"从文件末尾切验证集"导致验证集多轮占比是训练集的 2 倍多——SFT 验证损失 1.956 与 mini 时代 0.539 不可比，根因在此。

### 3.2 模型表现基线（multiturn.html 四套件实测）

| 套件 | 指标 | 我方模型 | 官方权重对照 |
|---|---|---|---|
| A 跨轮记忆 | 首轮告知的信息（姓名/年龄/暗号等），末轮追问能否召回 | **16.7%**（12 个关键词命中 2 个） | 33.3% |
| B 长度压力 | 上下文加长到 1024/1536/2048 token 后的回答质量 | 回答退化成 **5-18 token 的敷衍短句**（信息放弃，非复读） | 768 以上部分跑题 |
| C 长会话稳定 | 连续 12 轮对话，最后 3 轮的自我重复率 | **0.454**（第 12 轮单轮达 0.653） | 0.588（更差） |
| D 超长边界 | 输入约 39990 token（超 RoPE 表 32768） | **直接抛出底层张量异常崩溃**，无任何提示 | 同 |

归因结论（multiturn §根因）：官方权重用同一份数据训练，缺陷同样存在且更严重——**问题主要来自数据与截断处理，不是训练框架实现引入**。

### 3.3 现有产物与算力

- 权重：`out/pretrain_768.pth`（380 窗口预训练）→ `out/full_sft_768.pth` → `out/dpo_768.pth`
- 数据：`pretrain_t2t.jsonl` 8.3GB（847 万行）· `sft_t2t.jsonl` 14GB（511 万行）· `dpo.jsonl` 54MB（1.7 万对）
- 硬件：2 × RTX 4090 24GB（无 NVLink），预训练实测双卡 ~249K token/s

## 4. 目标

目标分两类，**验证方式完全不同**，必须分开看：

- **第一类（代码修复目标）**：只要改完代码、单元测试通过，就必然成立——由代码逻辑本身保证，不需要训练来验证。例如"不完整回复数 = 0"：新的截断逻辑按完整轮次保留对话，结构上不可能产生半截回复。
- **第二类（模型能力目标）**：必须在新数据上重新训练后、用同一评测工具复测才能确认。例如"跨轮记忆召回率 ≥60%"。

### 4.1 第一类：代码修复目标（阶段 1 完成后逐项验收）

| 指标 | 基线 | 目标 | 验证方式 |
|---|---|---|---|
| 完整回复保留率（1536 窗口） | 45.6% | **100%** | 单测 + `len_profile` 复测 |
| 被当作学习目标的不完整回复数 | 0.82 个/受损样本 | **0** | 单测 + `len_profile` 复测 |
| 零损失样本占比 | 5.7% | **0** | 构建期计数断言 |
| 回复精确重复率 | 8.6% | **<1%** | `data_profile` 复测 |
| 验证集/训练集多轮占比差 | ~21 个百分点 | **≤2 个百分点** | 构建期断言 |

### 4.2 第二类：模型能力目标（重训后复测）

| 指标 | 基线 | 目标 |
|---|---|---|
| 跨轮记忆召回（套件 A） | 16.7% | **≥60%** |
| 末 3 轮重复率（套件 C） | 0.454 | **<0.2** |
| 套件 B 1024/1536 token 档 | 回答退化成敷衍短句 | 切题且生成长度正常（>40 token） |
| 套件 B 2048 token 档 | 同上 | 切题（进阶目标，受底座限制，见 §10） |

## 6. 阶段 0：零成本基线测量 + 推理侧止血（~1 天，可与阶段 1 并行）

### 6.1 修正 YaRN 配置错误并测出"纯外推天花板"

**已核实的配置错误**：YaRN 插值参数 `original_max_position_embeddings`（含义：告诉插值算法"模型在多长的窗口上训练过"）硬编码为 **2048**，而模型实际训练窗口只有 **380**——算法把模型当成"在 2048 内训过"来外推，参数失真，外推质量被系统性低估。

两处硬编码位置：`src/minimind_reborn/models/config.py:65`（构造处）与 `src/minimind_reborn/models/layers.py:45`（兜底默认值）。建议顺手抽成常量或从配置透传，消除双源。

改动后用现有权重开 `inference_rope_scaling` 重跑套件 B：

**验收**：产出 `out/multiturn_eval_yarn.md`——不做任何训练时各长度档的切题率/生成长度表。此表回答"训练值不值"：若纯外推已让 1536/2048 档切题，训练侧长上下文的边际收益集中在质量而非能力，档二优先级可下调。

### 6.2 推理侧止血

- 会话类加 token 预算 + 滑动窗口：历史超预算时丢弃最旧轮次（系统提示恒保留——与阶段 1 训练侧的截断策略同构，两侧口径一致）。
- 推理引擎加输入长度硬校验：超过 32768 时报中文明确错误（"请缩短输入或开启 YaRN"），消灭张量形状裸崩溃。

**验收**：单测覆盖超限输入与滑窗路径；12 轮长会话末 3 轮重复率在滑窗加持下复测对照。

## 7. 阶段 1：数据管线修复（~1 天，不重训即对下次训练生效）

五项全部在 `src/minimind_reborn/data/`，互不依赖、可一次提交。**两个实现约束**：

- **惰性架构**：数据集按字节偏移惰性加载（`datasets.py`），511 万行全量分词的构建期扫描不可行——过滤必须用惰性重映射，去重/切分所需的一次性全量信息走旁车清单（见 7.0）。
- **工具同源**：`len_profile.py` 目前独立实现了一套截断/损失区间语义（L97-119），修复后必须与 `SFTDataset` 共享同一实现，杜绝"画像工具与训练代码各说各话"。

### 7.0 前置：构建扫描清单（manifest）

一次全量扫描（解析 jsonl 取轮数 + 回复规范化哈希，**不做分词**，14GB 约 10-20 分钟）产出旁车文件（如 `data_root/sft_t2t.manifest.npy`，记录每行的回复哈希、是否保留、训练/验证归属、轮数），以源文件修改时间+大小指纹失效重算。7.3/7.4/7.5 共用此清单，剔除量与分布断言写入该次运行的 `config.json` 快照（补上"数据卡"记录）。

### 7.1 修复一（C1）：按完整轮次截断，不再拦腰切

- **改动点**：`data/datasets.py` 的 `SFTDataset._encode_prompt`（L195-200，现为 `input_ids[:max_length]` 一刀切）。
- **策略**（渲染整段分词后）：
  1. 总长不超预算：原样保留。
  2. 超预算：从最旧轮次开始整轮丢弃（系统提示恒保留），直到装下或只剩系统提示 + 最后一轮。
  3. 仍超预算：截短最后一轮的**用户提问**（保尾部），助手回复永不截断——监督目标的完整性优先。
  4. 极端情况：单条助手回复本身超预算 → 按 7.2 规则该段无完整结尾、标签全 -100 → 被 7.3 过滤剔除并计数（罕见，记入数据卡）。
- **单测**：构造超长多轮样本，验证任意预算下输出无残段、系统提示在场、最后一轮完整、丢轮从最旧开始。

### 7.2 修复二（C2）：不完整回复不再当作学习目标

- **改动点**：`data/loss_mask.py` 的 `find_response_spans`（L31-33）——现找不到回复结尾标记时仍把残段划入损失区间。改为：**结尾标记完整匹配才计入损失区间**，尾部残段整段不进监督（等价标签 -100）。
- **单测**：`tests/test_data/test_loss_mask.py` 增补——截断样本的残段标签全 -100；完整样本的掩码与现行为逐位一致（防回归，这一语义是与官方权重互通的脆耦合）。
- **配套**：`len_profile.py` 增加"不完整回复数"统计项，把这个问题从此可测量。

### 7.3 修复三（C3）：零损失样本过滤

- **改动点**：`SFTDataset.__getitem__`（惰性）——编码后标签全为 -100 则**确定性重映射**到下一个可用样本（`i+1` 起向前探测，有界；同一序号恒定映射到同一样本，保证双卡训练时两个进程看到一致的数据）。
- **计数出口**：剔除量写入运行配置快照（数据卡）。
- **单测**：构造全 -100 样本 → 重映射命中非零样本、计数正确、双进程映射一致。

### 7.4 修复四（C4）：回复去重

- **改动点**：manifest 按回复规范化哈希（小写 + 去空白标点）去重，保留首现；数据集读清单的"是否保留"列直接跳过重复行。
- **验收**：`data_profile.py` 复测（10 万行采样）——回复精确重复率 8.6% → **<1%**，指令前缀重复率同步下降。

### 7.5 修复五（C5）：训练/验证集按内容哈希切分

- **改动点**：`_tail_split`（L103-106，现为文件尾部切片）改为哈希分桶——扫描时按规范化行内容哈希决定归属（如哈希 % 1000 == 0 进验证集），与顺序无关；构建期断言**验证集与训练集的多轮占比差 ≤2 个百分点**，违反即报错。
- **连带事项**：验证集口径更换后旧分数作废——阶段 2 重训前，先用现有权重在新验证集上重评一次，建立可比新基线。

## 8. 阶段 2：档一重训 SFT（窗口 1536）+ DPO（~26h GPU）

### 8.1 前置

```bash
uv run python tools/len_profile.py --name sft_t2t --train-seq 1536 --sample 100000
uv run python tools/train.py configs/smoke/smoke_sft.yaml \
  --set data.max_seq_len=1536 --set train.batch_size=8 --set train.max_steps=60
```

冒烟核查三项：显存余量、损失正常下降、吞吐与预计到达时间（metrics.jsonl 自带 MFU/ETA，用实测值修正 §8.3 预估）。
**回退线**：1536 对 380 底座属于 4 倍窗口外推微调，若冒烟时损失不降或震荡，回退窗口 1024，其余不变。

### 8.2 新配方 `configs/sft_full_lc.yaml`

```yaml
# 64M 长上下文 SFT（管线修复后全量 sft_t2t，seq 1536）
stage: sft
data:
  dataset: sft_t2t
  max_seq_len: 1536       # 768 → 1536：绝大多数多轮会话（p90=1633）装进窗口
  eval_ratio: 0.003       # 修复五后为哈希分桶口径
  num_workers: 4
train:
  epochs: 2
  batch_size: 8           # 8×1536 = 16×768，单批 token 数不变
  gradient_accumulation_steps: 2   # 累积后每优化步样本数 = 旧配方的 16，token/step 等量
  learning_rate: 1.0e-5   # 不变，控制变量
  dtype: bf16
  init_from: pretrain     # 现有 out/pretrain_768.pth
  save_interval_steps: 2000
  log_interval: 100
metrics:
  backends: ["tensorboard"]
```

### 8.3 成本核算（冒烟后用实测 ETA 修正）

数据集逐样本填充到窗口长度（无拼包），故计算量 ∝ 样本数 × 轮数 × 窗口长度。窗口 768→1536：线性部分 ×2，注意力二次项另加约 15%（64M/GQA/SDPA 下注意力约占 14%）→ 实测 FLOPs ≈ **2.3×**。全量 SFT@768 实测 11.3h → **@1536 ≈ 26h**（双卡）。

> 若填充浪费成为瓶颈（轮次截断后短样本占比升高），备选优化为动态填充 / 按长度分桶组批——列为实验项，不阻塞主线。

### 8.4 DPO

沿用 `configs/dpo_full.yaml`（窗口 1024、配对级截断仅 2.8%、学习率 4e-8、β 0.15），起点指向新 SFT 权重，约 5 分钟。

### 9.2 决策点 1：多轮数据是否增强（已选"先复测定标"）

- **召回 ≥60% 且末 3 轮重复 <0.2** → 不增强，直接看决策点 2。
- **否则触发增强**（预期路径：阶段 1 把多轮监督信号从名义值的 ~37% 恢复到 ~100%，但 19.4% 的占比天花板仍在）：

  - 实现：manifest 加上采样列 + 数据集索引展开（0.5 天，含画像复测），不改数据文件本身。
  - 过拟合监控：训练/验证损失差超过 15% 即回退上采样倍数；复测套件 A/C。
  - 增强后需再训一次 SFT（+26h GPU）。
  - 开源多轮数据集混入列为次选：+1-2 天数据工程 + 去污染验证，仅在上采样仍不达标时启动。

### 9.3 决策点 2：是否进档二、走哪条路线

对比**档一套件 B** 与**阶段 0 纯外推基线**：

- 档一后 1536/2048 档仍退化、且明显差于纯外推可解释的范围 → 底座 380 的位置编码已是瓶颈，**进档二路线 4a（续训）**。

- 4a 后仍不达标才动 4b（从头重训，§10.3）。

## 10. 阶段 4：档二——长上下文底座

### 10.1 路线 4a（推荐）：续训（继续预训练，本阶段约 2h GPU）

**原理**：底座的位置编码已学好"相对位置"的通用模式，缺的只是"见过长序列"。加载现有预训练权重、加长窗口、降低学习率继续预训练即可。已核实代码支持：`train.init_from` 定义在跨范式共享的 `TrainConfig`（`schemas.py:81`），由训练基件统一消费（`trainer.py:417`），**预训练工作流同样生效——续训只需新配置文件，零代码改动**。（LLaMA-2 4K→32K、Qwen 长上下文扩展同为续训路线。）

**数据**（避开填充浪费是关键动机）：预训练数据集逐样本填充到窗口长度（`datasets.py:139-150`，无拼包）——全量数据在 1536 窗口下，一半样本（长度中位数 285 token）的填充率超过 80%，纯烧算力。改为：

- **长文档子集**：不低于 768 token 的文档估计占 **~25%（约 210 万条）**——介于两个实测锚点之间（≥380 占 30.7%、≥1024 占 20.8%），正是 380 窗口时代被截断丢弃 45% 的那批文档，续训恰好回收；精确占比由构建工具实测校准。
- **构建工具** `tools/build_longctx_subset.py`（新建，约 0.5 天）：字符阈值近似筛选 + 1000 行抽样校准 token 阈值（精度 ≥90%）+ **token 预算裁剪**（默认 0.5-1B 内容 token，约 40-80 万条，种子 42 确定性）+ **混入 20-30% 短文档回放防遗忘**；注册数据集名 `pretrain_longctx`。

**配方 `configs/pretrain_longctx.yaml`**：

```yaml
# 长上下文续训：预训练权重 + 长文档子集 + 窗口 1536
stage: pretrain
data:
  dataset: pretrain_longctx
  max_seq_len: 1536
  eval_ratio: 0.003
  num_workers: 4
train:
  epochs: 1
  batch_size: 16          # 单批 16×1536=24,576 token；每优化步 16×4×1536≈98K ≈ 旧配方 32×8×380≈97K
  gradient_accumulation_steps: 4
  learning_rate: 5.0e-5   # 原峰值 5e-4 的 1/10：续训是"适应长度"不是"学新知识"，防冲乱底座
  warmup_steps: 200       # 加载权重后续训必须热身（从零训练的官方配方无热身，不适用于续训）
  lr_min_ratio: 0.1       # 余弦退火下限 = 5e-6
  dtype: bf16
  init_from: pretrain     # 现有 out/pretrain_768.pth，严格加载
  save_interval_steps: 1000
metrics:
  backends: ["tensorboard"]
```

- **RoPE 频率基数**（theta 1e6）不动——1536 窗口下分辨率充足；调高 theta 或训练期开插值属二线实验手段，仅在 4a/4b 后仍不达标时评估。
- **回退线**：续训损失发散 → 学习率降至 2e-5 或窗口降至 1024。
- **成本**：0.5-1B 内容 token ≈ 0.55-1.1B 填充后 token，双卡约 200K token/s → **0.8-1.5 小时**。
- **衔接**：续训权重 → SFT（窗口 1536，§8.2 配方改起点）→ DPO。**全链约 28h**。

### 10.2 4a 前置验收

```bash
uv run python tools/len_profile.py --name pretrain_longctx --train-seq 1536 --sample 100000
```

子集构造后保留率应 **≥85%**（长文档分布右尾仍会超 1536，右截损失计入保留率）；低于 85% 说明字符阈值筛选偏了（混入过多中短文档）或应上调窗口，回构建工具校准。

### 10.3 路线 4b（兜底）：预训练从头重训（窗口 768，约 16h GPU）

仅当 **4a 续训后套件 B 1536/2048 档仍不达标**（续训受 380 底座先验拖累的理论上限）才启动：

- **前置**：`len_profile --name pretrain_t2t --train-seq 768` 实测保留率（预计 54.8% → 75-85%）；**若窗口 1024 相对 768 的增量保留率超过 10 个百分点，窗口直接取 1024**（一步到位省一次重训）。
- **配方 `configs/pretrain_full_768.yaml`**：数据集 `pretrain_t2t`、窗口 768、批 16 × 累积 8（每步 token 数与旧配方等量）、学习率 5e-4 不变（控制变量）、2 轮。填充后计算量 ×2.0 + 注意力 ≈ **2.24×** → 7.1h × 2.24 ≈ **16h**。
- 全链：预训练（16h）→ SFT@1536（26h）→ DPO ≈ **42h**。
- 可选实验（风险自担）：训练期开插值或调高 theta——与 4b 组合前先冒烟。

### 10.4 两路线对照

| | 4a 续训（推荐） | 4b 从头重训（兜底） |
|---|---|---|
| 前置成本 | 零代码 + 0.5 天子集工具 | 零（换配置即跑） |
| 本阶段 GPU 时长 | ~2h | ~16h |
| 全链（含 SFT+DPO） | ~28h | ~42h |
| 底座知识 | 保留（可随时回退） | 重建（质量重置，方差大） |
| 长度上限预期 | 受 380 先验拖累，1536 档收益确定、2048 档待验 | 与从头训练同上限 |
| 触发条件 | 默认路线 | 4a 后套件 B 仍差才触发 |

### 11.2 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| **输出权重同名覆盖**：训练工作流的保存名硬编码（`pretrain`/`full_sft`/`dpo` → `out/*_768.pth`），重训会覆盖现有基线权重，评测脚本的对照路径随之失效 | 高（不可逆丢基线） | 每次重训前归档 `out/*.pth` → `out/archive/era1/`（或给工作流加可配置保存名，小改动）；归档动作已列入 §1.2 任务 2.3 |

| 长训练中断 | 低 | `save_interval_steps: 1000`（约每 8.5 分钟一个恢复点；readiness §1 已验证强杀续训偏差 0.67%） |

| 阶段 | 内容 | 耗时 |
|---|---|---|
| 0 | YaRN 基线 + 推理止血 | ~1 天（可与阶段 1 并行），GPU ~0.2h |
