01特征字典：每个特征是什么、怎么算、怎么测、怎么比

对比模型之前必须先讲清「尺子」。本章 10 个特征全部是本项目实际测过的，每个按统一四段式说明。总原则：特征对比只在「同一测量方式」（同评测集、同随机种子、同判定规则）下有意义——本项目全部评测固定 seed 42。

1.1 交叉熵损失（CE loss）与困惑度（PPL）

是什么：模型对文本的预测不确定度。CE = 每个 token 的 −log P(正确词) 的平均值；PPL = exp(CE)，直观含义是「平均每个位置等效于在多少个词里犹豫」。CE 2.0 ≈ PPL 7.4。

怎么算/怎么测：固定一组文本，让模型逐位置预测下一个词，对正确词的概率取负对数平均。本项目工具：tools/eval_val_baseline.py（token 加权平均）与训练内验证（固定 50 批次）。注意本项目 SFT 只在「助手回答」的 token 上计损。

怎么比：越低越好。陷阱（本项目踩过三次）：① 验证集切法不同不可比（旧尾切验证集被多轮对话富集，同模型同权重在旧/新验证集上分别是 2.04 / 1.23）；② 训练内验证带随机系统提示增强、逐批平均，与外部脚本的无增强、token 加权是两套口径（档一 1.2666 与档二 1.2677 不能直接比大小——两者验证集也不同，档二含 Belle 数据）；③ 跨能力域不可比（预训练与微调的损失基底不同）。正确用法：同一模型在两个验证集上比（揭示数据问题），或两个模型在同一验证集上比（揭示模型差异）。

1.2 跨轮记忆召回率（套件 A）

是什么：多轮对话中「听过→记住→取回」链路的完整度。对话前面轮次注入的事实（姓名/年龄/数字/暗号），若干轮后追问能否说出。

怎么算：4 个剧本共 12 个关键词；在指定追问轮的回答文本里做子串命中，召回率 = 命中数 / 12。

怎么测：tools/eval_multiturn.py --suites A，温度 0.7 / top_p 0.9，全历史重渲染。

怎么比：越高越好，60% 是本项目定的可用线。局限（必读）：子串命中≠语义理解——档一案例「蓝天白云」是字面照抄但语义仍胡解的弱命中；因此本章对比同时使用 1.3 的归因细分来补深度。

1.3 命中归因细分：「复述过的」vs「仅用户说过的」（本项目自建口径）

是什么：把召回命中再分两类——模型自己早前回复里逐字说过的（上下文自复制即可答对）vs 只有用户说过、模型从未复述的（必须真正「听」用户）。档一 50% 的 6 个命中全部是前者——「学会了复制自己，没学会倾听用户」的结论就来自这个口径。

怎么算：人工核对逐用例全文（out/multiturn_samples/suiteA_*.md），逐关键词回溯它是否出现在该模型此前任何一轮的回复中。

怎么比：「仅用户说过」类命中数的增长 = 真倾听能力的增长。档二的关键证据：算术用例的 17/35/900（旧模型从未复述过）首次全部命中。

1.4 n-gram 重复率（复读检测）

是什么：生成文本的自我复读程度——卡在同一句式循环输出的直接信号。

怎么算：生成文本中重复出现的 n 元词组占比（本项目 n=3）。

怎么测：套件 C 逐轮记录（12 轮会话每轮一个值）。

怎么比：单轮高（如 0.95）= 该轮已陷入复读循环；会话末段 vs 前段的变化才是「长会话退化」的特征（见 1.9）。注意区分复读与「敷衍短句」——重复率 0 但只生成 11 个词是另一种失败（信息放弃）。

1.5 生成长度（token 数）

是什么：回答的信息量粗代理。同一问题下，模型愿意展开多少内容。

怎么测：套件 B/C 逐条记录生成 token 数（上限 192，防失控）。

怎么比：形态比数字重要——本项目三代模型在长上下文压力下都是 9-11 token 的「敷衍短句」形态（对比正常回答的 50+ token），这是「对超训练窗上下文放弃作答」的特征签名；而 192 token + 0.95 重复率则是复读失控。两种形态指向不同病根。

1.6 在题率（回答相关性）

是什么：回答是否针对所问（不跑题）。

怎么算：本项目为脚本启发式初判 + 人工核对样例（正式基准会用关键词/裁判模型）。

怎么比：跑题通常出现在上下文超过训练窗后（注意力被窗外的位置分布带偏）。official 在 768/1536/2048 档跑题而本项目模型在题（但敷衍）——两种不同的退化模式。

1.7 分长度档表现（套件 B）

是什么：把对话历史垫长到 256/512/768/1024/1536/2048 六档再提问，观察各档的回答质量——训练窗内外推行为的直接探针。

怎么测：tools/eval_multiturn.py --suites B，合成填充历史 + 固定问题。

怎么比：训练窗内（≤1536）应稳定；窗外档的质量变化反映位置编码外推能力。YaRN 免训练外推在本项目实测为负收益（1536/2048 档恶化成复读循环）——说明「位置编码插值」救不了没见过长序列的底座。

1.8 长文档交叉熵（底座长位置建模能力）

是什么：预训练底座在长文本（本项目取 ≥1024 token，1536 窗口）上的语言建模质量——长上下文能力的「原材料」指标，与对话能力正交。

怎么测：tools/eval_cont_train.py：新旧底座各算 200 条长文档的 token 加权 CE，同时算 200 条短文档 CE 作防遗忘对照。

怎么比：长文档 CE 显著下降且短文档劣化 ≤5%，说明「长上下文续训」既有效又没冲坏原有能力。档二实测：长 −20.7% / 短 +4.28%。

1.9 长会话退化斜率（前 3 / 末 3 轮重复率）

是什么：连续 12 轮对话中，复读倾向随轮次的增长——「越聊越崩」的速度。

怎么算：套件 C 逐轮 3-gram 重复率，取前 3 轮均值与末 3 轮均值之差。

怎么比：末 3 ≈ 前 3 = 无退化；差值越大退化越快。三代模型：0.373（era1）→ 0.221（档一）→ 0.016（档二）——档二几乎零退化。

1.10 边界行为（超长输入）

是什么：输入超过模型位置编码表容量（32,768）时的行为——崩溃、静默截断还是明确报错。

怎么测：套件 D（39,990 token 输入）。怎么比：工程特征而非能力特征——修复在推理引擎侧（明确中文报错 + 提示缩短或开外推），模型侧本身仍会张量形状错误，评测如实记录。

2.2 逐特征解读：改进了什么、为什么

召回率的两级跳各有不同来源。16.7%→50% 发生在数据管线修复后（监督信号从名义值 37% 恢复到 100%），但归因细分显示档一的 6 个命中全是「自己复述过的」——机制上是上下文自复制；50%→75% 发生在多轮数据增强后，且增量证据（算术用例 3 个数字、精确姓名「李小明」）来自「仅用户说过」类——Belle 真实多轮对话里的「引用用户信息」模式被学到，即「倾听」能力的实证。两级增益来源不同，恰好验证了「先修管线、再补数据模式」的顺序正确性。

长会话稳定性的改善与数据结构直接对应。残段修复（不再教「半截话」）解释档一的 0.454→0.283；深多轮样本 3.9%→12.7% 解释档二的 0.283→0.086——12 轮会话的「素材」从几乎没有到充足，退化斜率几乎归零（0.016）。official 同数据旧管线 0.588 作反证。

B 档不动是最有信息量的「负结果」。档二动了底座（长文档 CE −20.7%）、动了数据（多轮 41.7%），但合成长历史场景下仍是敷衍短句。结合底座指标显著改善而 B 不变，可以排除「底座长文本建模不足」这个解释——剩余解释是：该场景（超长合成历史+固定提问）在训练分布中不存在，模型的生成分布没有对应的信号。特征组合的交叉验证把病根从「能力」改判为「分布缺失」，这是第 6 章方案 1 的直接依据。

新增的 512 档复读点（「在讨论中，我提到过」循环）：句式恰似 Belle「引用讨论历史」模式的退化解——单一档位触发（其余档位正常），是增强数据带来的局部副作用，列入下一步针对性处理。
