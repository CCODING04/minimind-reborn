# 多轮/连续对话能力检测

## 结论（先读）

**判定：全量训练三模型（base/SFT/DPO）的连续对话能力存在明确缺陷，主要源自训练数据结构，非推理实现引入。**

| # | 缺陷 | 严重度 | 证据 |
|---|---|---|---|
| 1 | **跨轮记忆缺失**：无法记住同会话内用户 earlier 声明（姓名/数字/暗号） | 高 | Suite A：ours dpo/SFT 召回率仅 **16.7%**，官方权重 **33.3%**（同数据训练，同样差）；单轮内的算术（525 元）反而正确——是"跨轮"而非"推理"问题 |
| 2 | **多轮训练数据占比过低且被截断损毁**（根因，2026-09-25 修正） | 高 | 全量随机采样（10 万行）：多轮样本占 **19.4%**（80.6% 单轮）；且文件有序——头部/中部 100% 单轮、尾部 39.4% 多轮；768 截断会砍掉多轮对话的后半段。（初版"0% 多轮"系文件头 1000 行有偏抽查所致，特此修正） |
| 3 | **长会话后期退化**：重复率从 0.08 涨到 0.45（ours）/ 0.59（official），10 轮后进入复读循环 | 中高 | Suite C 轮 10"回答了几个问题"完全无历史概念；轮 11-12 重复率 0.54/0.65，卡在模板循环 |
| 4 | **有效上下文远短于标称 32K** | 中 | 训练最长 768 tok（SFT）/380（pretrain）；Suite B 中 2048 tok prompt 下回答已退化到 5-10 tok 的敷衍短句（官方在 768/1536/2048 三档跑题） |
| 5 | **超 32768 tok 无守卫** | 中（工程） | Suite D 实测：prompt 39990 tok → 裸 `RuntimeError: size of tensor a (39990) must match b (32768)`，无清晰报错指引；tokenizer 截断上限 131072 与 RoPE 表 32768 脱节 |

**归因**：官方权重（同 sft_t2t 数据训练）同样表现出缺陷 1/3 且更差（召回 33.3% vs 我们 16.7% 是官方略好，但后期重复率 0.588 比我们 0.454 更差）——
**缺陷随数据继承，非 minimind_reborn 实现引入**；实现侧唯一新增问题是缺陷 5 的守卫缺口。

**修复方向**（附录，本轮不实施）：
① SFT 数据混入多轮样本（loss mask 已天然支持多回答区间——`find_response_spans` 扫描全部 assistant 区间，数据层零改动）；
② 推理侧加历史 token 预算（滑窗或摘要压缩，ChatSession 单点改动）；
③ 768→2K+ 的长度外推需 YaRN（`inference_rope_scaling` 已支持）或混入长序列训练；
④ prompt 长度超 `max_position_embeddings` 时显式报错（engine 单点守卫）。

**测试口径**：Suite A 4 组剧本 × 召回关键词、Suite B 6 档长度 × 固定问题、Suite C 12 轮固定问题链、Suite D 40000 tok 越界；seed 42 统一；
温度 0.7 / top_p 0.9 / max_new_tokens 192。样例全文见 out/multiturn_samples/。
